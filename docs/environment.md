# Environment keys

The house's own keys are in `.env`: `secrets.env.example` documents the core's, and each plug-in's
`setup/env.example` its own (`make install` / `make update` append the keys `.env` lacks and fill the
generated ones). An empty value means the default. `make install` / `make update` replace `.env` by a
checked copy: keep it a regular file, not a symlink (a link would be replaced by a file).

Host pieces read env files of their own, `/etc/yashome/<piece>.env` (the SwitchBot bridge:
`/etc/yashome/switchbot-<id>.env`, one per lock); an example lies next to the piece
for presence (`host/presence.env.example`), switchbot (`host/switchbot.env.example`) and provision
(`host/provision.env.example`: only the Wi-Fi card, optional). The Wake-on-LAN relay, the provision relay and
panel-start take no port and no token: `sudo sh tools/host-sockets.sh` installs them on socket files in
`/run/yashome`, the house's group only.
The touchmouse receiver reads `TOUCHMOUSE_PORT` (7709) and `TOUCHMOUSE_BIND` from
`/etc/yashome/touchmouse.env` (see its README); it and its typing helper share `TOUCHMOUSE_TYPE_PORT` (7710, loopback).

Keys outside the house's `.env` - set by a compose file, an image, a build script, or the code's
default. A test (`tests/test_envlib.py`) checks that every key the code reads is named in some
documentation:

| key | where | what |
|---|---|---|
| `HOUSE_ROOT` | home | `/house`, the mounted `HOUSE_DIR` |
| `YASHOME_RESTRICTED` (or `YASHOME_DEMO`) | home | set by a public demo's compose file: `1` = restricted mode, a route runs only when a plug-in allows it (docs/security.md) |
| `MQTT_HOST_PORT` | home | the broker port nodes on the network connect to (`MQTT_PORT`; host:port allowed) |
| `HELPER_URL` | home | the update helper (`http://helper:8796`) |
| `HELPER_PORT`, `HELPER_BIND`, `HELPER_IMAGE` | helper | the code's defaults: 8796, 0.0.0.0 (the helper network only), `yashome-helper:local` |
| `GIT_SSH_COMMAND` | helper | the deploy key for `git pull` (Settings -> Plug-ins and update -> Update) |
| `YASHOME_JOB` | helper's job container | set by the helper: `make` steps that need the host's home skip them |
| `STATE_DIR` | panels-discover | `/state`: its `pairing.json` / `discovered.json` |
| `APK_URL`, `BUILD_PORT`, `BUILD_WORK`, `BUILD_MODE`, `ESPHOME_BIN`, `GRADLE_USER_HOME` | build server, app builder (on a computer of the house) | see `plugins/tools/build/README.md` |
| `MQTT_HOST` | home | the broker inside the compose network: `mosquitto` (the stand sets its own) |
| `HOST_SOCKETS_DIR` | home | the folder of the house's helpers on its host (`tools/hostsock.py`): `/run/yashome`; the stand and the tests point it elsewhere so a copy of a house reaches no real tablet or wake |
| `ANDROID_KEYSTORE_FILE`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` | the apps' `build.sh`, the app builder | the signing key: set by `build.sh` only when the house has `app.keystore` and `app.keystore.pass`; the build server sets the password and alias per job |
| `YASH_FB_DB`, `YASH_FB_KEY`, `YASH_STATE_CFG`, `BRIDGE_KEY`, `BRIDGE_PORT`, `MQTT_HOST`, `MQTT_PORT`, `MQTT_USER`, `MQTT_PASS`, `YASH_I18N`, `YASH_QR_DIR` | family-bridge | see `plugins/tools/family/README.md` |
| `LISTEN_FDS` | the WoL relay, the provision relay (on the host) | set by systemd when it hands a socket of `tools/host-sockets.sh` over; started without it, they refuse |
| `STAND_DIR` | `tools/stand.py` | where the throwaway stand keeps its house, token and log (default: the temp dir's `yashome-stand`) |
| `STAND_PLUGINS` | `tools/stand.py` | the plug-ins the stand's backend loads (default: none, the core only) |
| `HOME_STACK_ROOT` | tests | the fixture tree the core runs on in a test, instead of the checkout |
| `HOUSE_WORDS` | `tools/check_plugins.py` | words of your house that must not appear in the code (or `.house-words`) |

The voice plug-in's TTS service reads `VOICE_TTS_KEY` (generated by `make install`; the key the plug-in calls it with), `VOICE_TTS_THREADS` (torch threads, default 2), `VOICE_TTS_PORT`, `VOICE_TTS_DATA` and `VOICE_TTS_MODELS` (inside the container: the port 8092, `/data`, `/models`), and on a computer of the house `VOICE_TTS_OPEN` (no key: its loopback only); its port is published at `BIND_ADDRESS`, where the satellites fetch the spoken files. The background recording "while the TV is on" watches the TV of the satellite's room (or the house's only one).
